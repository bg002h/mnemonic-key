## C3 in depth — the counterexample

**The fold's remedy, as narrated in the commit message, was "a terminal otherwise
arm." The remedy actually written is not terminal — it carries a precondition
that excludes a case r1 itself named.**

Spec text (situation 3): *"received = declared, headers consistent, but
reassembly or bytecode decode fails"* → terminal otherwise, carries the codec
error verbatim.

Construct: three mk1 chunk strings sharing one `chunk_set_id`. All three
declare **the same** `total_chunks = 2` (no disagreement — situation 1's second
branch is false). Their `chunk_index` values are `0, 1, 2` — **all distinct**,
so no duplicate (situation 1's first branch is false too). `received = 3`,
`declared = 2`, so `received > declared` — **not** situation 2, which is
strictly `received < declared`. `received (3) ≠ declared (2)`, so situation 3's
own precondition is false — it is never reached, so its "otherwise" clause
never fires. Situation 4 requires clean reassembly, which does not occur (an
index of 2 against `total_chunks = 2` is out of range).

This is not a hypothetical: mk-codec's own reassembly code has exactly this
branch, already named by r1 as one of the "three further uncovered exits":

```
crates/mk-codec/src/string_layer/chunk.rs:248-252
if idx >= total_usize {
    return Err(Error::ChunkedHeaderMalformed(format!(
        "chunk_index {idx} >= total_chunks {total}"
    )));
}
```

And by the pigeonhole argument, this is the *general* shape of the gap, not
a one-off: any group with a single consistent `total_chunks = T`, no duplicate
indices, and `received > T` **must** contain at least one index `>= T` (there
are only T valid slots `0..T` for `T` or fewer distinct values to fit in
without collision) — so "received > declared, no duplicates, single T" and
"contains an out-of-range index" are the same case, and neither situation 1,
2, nor 3 as worded catches it.

`MixedHeaderTypes` (`chunk.rs:264`, r1's other named uncovered exit) **is**
correctly precluded — verified in `descriptor-mnemonic crates/md-cli/src/seat/
input.rs:143-158` (`group_key_of`): a `SingleString` header is keyed by input
position (`GroupId::Single(position)`), never by `chunk_set_id`, so it can
never land in the same group as `Chunked` strings under md-cli's own grouping.
That sub-case is a non-issue for the seat path specifically (though still live
for direct `mk_codec::decode` callers, which are out of this spec's contract-2
surface list already).

**Disposition:** C3 is fixed for the case that motivated it (the measured
merged-cards scenario, which the fold correctly re-verified this session per
its own commit message) but is not fixed for the sibling case r1 filed under
the same finding. Per the brief, an unfixed r1 finding keeps its tier — C3
**stays Critical, PARTIAL**, not FIXED.

**Remedy direction (advisory, not authoritative):** drop the `received =
declared` clause from situation 3's precondition — the situation should read
"not situation 1, not situation 2 (i.e., `received >= declared`), but
reassembly or bytecode decode fails" — which subsumes the out-of-range-index
case without adding a fifth named situation, and matches what the commit
message already claims was built.
