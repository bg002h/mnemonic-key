### C1 · Critical · A fixed WIF key card produces HD child addresses

**Entry points** — `mk address` at `crates/mk-cli/src/cmd/address.rs:86`, `:118`, and `mk derive` at `crates/mk-cli/src/cmd/derive.rs:73`. The fixed-key representation is documented in `design/SPEC_mk_no_path_support.md:12` and `:183`. The toolkit actually constructs it in `../mnemonic-toolkit/crates/mnemonic-toolkit/src/cmd/bundle.rs:808` (sibling revision `9069ad83`).

```bash
LEAF=tpubD6NzVbkrYhZ4WLczPJWReQycCJdd6YVWXubbVUFnJ5KgU5MDQrD998ZJLT5hqNKRA9cJzkh4D7oXwCpwFUWWWkHR9zPeBk1hnWBJKNhyYsn
"$MK" encode --xpub "$LEAF" --origin-path m --privacy-preserving --policy-id-stub deadbeef > leaf.mk1
"$MK" address --in leaf.mk1 --address-type p2wpkh --network signet --count 1
"$MK" derive --in leaf.mk1 --index 0 --json
```

The fixture has the public generator point, empty origin, depth zero, zero parent fingerprint, child zero and a zero chain code. The direct signet P2WPKH address of its public point is `tb1qw508d6qejxtdg4y5r3zarvary0c5xw7kxpjzsx`. The address command exited 0 with **`tb1qgl57xjd595rrxmpwys85q40xh4nmqunqrmrmwp`**. It printed the ordinary depth advisory. Derive exited 0 with a depth-two child. An ordinary fixed-key import does not watch that child. Accessing funds sent there would require reconstructing the CLI’s synthetic HD derivation from the original secret. The difference follows directly from `bitcoin::Address::p2wpkh(&leaf.to_pub(), bitcoin::KnownHrp::Testnets)` versus the CLI’s `m/0/0` derivation. No funds were sent.

**Fix and regression** — recognize the toolkit's complete fixed-key sentinel before either command attempts child derivation. Refuse child/range requests with a fixed-key diagnostic and empty payload. Keep the card readable and verifiable. Exercise the commands above and a genuine root tpub with the same point and nonzero chain code (the control with 32 bytes of `01` derived successfully). Update the broad proceed-with-advisory rule in `design/SPEC_mk_derive_address.md:47` to describe the fixed-key exception. Preserve that advisory for derivable root keys.

### I1 · Important · A failed output replacement destroys the previous card

**Entry point** — `mk encode --out FILE` calls the shared writer at `crates/mk-cli/src/cmd/encode.rs:440`. See `vendor/mnemonic-io-lib/src/write.rs:49,55,64`. The shared writer truncates the open file before the first payload write.

```python
# Run in D after the setup. Pass the built binary as argv[1].
import pathlib, resource, signal, subprocess, sys
p = pathlib.Path("acct.mk1")
old = p.read_bytes()
key = __import__("json").loads(subprocess.check_output(
    [sys.argv[1], "decode", "--json", "--in", str(p)]))["xpub"]
def limit():
    signal.signal(signal.SIGXFSZ, signal.SIG_IGN)
    resource.setrlimit(resource.RLIMIT_FSIZE, (8, 8))
r = subprocess.run([sys.argv[1], "encode", "--xpub", key, "--origin-path",
    "m/84'/0'/0'", "--origin-fingerprint", "73c5da0a",
    "--policy-id-stub", "deadbeef", "--out", str(p)], preexec_fn=limit)
print(r.returncode, len(old), p.read_bytes())
p.write_bytes(old)  # restore only this disposable fixture
```

Observed `64 193 b'mk1qp22l'`. The error accurately named the write failure, but neither the old nor the new backup survived. Unrestricted replacement succeeded. With an eight-byte regular-file stdout limit and SIGXFSZ ignored, the existing stdout sink correctly exited 1.

**Fix and regression** — for a regular destination, write a private temporary file in the same directory, check write/flush errors, then atomically replace the destination. Surface rename failures and remove the temporary. Keep the existing successful-overwrite and owner-only contracts. The test must assert byte identity of the *old* file after the failure, successful decode, and a successful replacement on retry. A nonzero status alone already passes. Change the upstream shared writer deliberately or implement the regular-file policy in mk, then update the dependency through its normal source.

### I2 · Important · A known cosigner can be minted with an origin its own md1 contradicts

**Entry point** — `mk encode --from-md1[-set]`, `crates/mk-cli/src/cmd/mod.rs:343` and `crates/mk-cli/src/cmd/encode.rs:306`. The complete cosigner extraction discards slot numbers and origin metadata after retaining the 65 key bytes.

```bash
"$MK" encode --xpub "$X0" --origin-path "m/48'/0'/9'/2'" \
    --origin-fingerprint 73c5da0a --from-md1-set keyed.md1 > crossed.mk1
"$MK" decode --in crossed.mk1 --json
```

The policy explicitly declares slot 0's key, shared path `m/48'/0'/0'/2'` and slot fingerprint `73c5da0a`. The mint exited 0, stamped `38bd7cec`, and decoded with account **9**. Changing just the fingerprint to `deadbeef` on the true path also exited 0. Neither changed the child number or depth. The ordinary “1 not carded” notice mentioned only the other cosigner. Actual slot 0 succeeds, and an unrelated third key is refused. Recovery §5.1 requires the orchestrator to reject a contradictory declared path.

**Fix and regression** — keep the matching slot indices, resolve the policy's per-slot paths and fingerprints, and reject a provable conflict before emitting any batch member. For repeated key identities, allow any matching slot with compatible declared metadata. Preserve explicit fingerprint omission, keyless templates and undecidable sparse membership. Run both crossed cases via single and batch input, assert refusal and absence of card output, then assert the correct-origin control still mints. Keep verify's documented stub comparison separate from mint validation.

### I3 · Important · Mixed line endings silently drop a cosigner

**Entry point** — `mk encode --keys/--in`, `crates/mk-cli/src/keyfile.rs:129,137`. One LF anywhere disables the CR-only guard. A carriage return after an inline comment leaves the next physical record inside that comment.

```bash
printf '%s # first\r%s\n' "$rec0" "$rec1" | "$MK" encode --keys - --policy-id-stub deadbeef --json
```

Exit 0, `card_count: 1`, only account 0. Replacing the bare CR with LF produced two cards, for accounts 0 and 1 in order. A bulk backup operator can take home a short set.

**Fix and regression** — handle physical line endings before stripping comments. Preserve the current refusal for bare CR if that is the intended policy, checking each occurrence even in mixed files. Test file and stdin input with the bytes above, normal LF/CRLF controls and two distinct expected xpubs. A successful one-card result must fail the regression.

### I10 · Important · A public Rust caller can round-trip a normal child into a hardened child

The command logged 41 vectors (35,487 bytes), then 21 extension rows (17,476 bytes), both on the same path. Exit 0, with only the extension corpus present. Using `v0.1.json` as the output produced two artifacts byte-identical to their checked-in counterparts.

**Fix and regression** — check that the two destinations are distinct before opening either. Include literal collisions and existing filesystem aliases, leaving both inputs intact on refusal. Test the colliding filename above and compare both normal output bodies to the pinned bytes.

### I17 · Important · The locked fuzz workspace fails before running its seed test

**Entry point** — standalone fuzz workspace at `fuzz/Cargo.lock:170–177` and CI at `.github/workflows/fuzz-smoke.yml:80,117`. The lock records mk-codec 0.4.2 and its former dependency, while this checkout provides 0.5.1.

From a pristine archive of the audited commit, `cd fuzz` and run `cargo +nightly-2026-04-27 test --locked --test gen_corpus`. It exited 101 because Cargo needed to update the lockfile. The workflow invokes cargo-fuzz without asserting lock freshness. After refreshing just the lock in a disposable copy, the same seed test passed and all three fuzz targets built and ran.

**Fix and regression** — refresh the standalone lockfile against this revision, then gate it independently of the root workspace. Run `cargo +nightly-2026-04-27 metadata --locked --offline --format-version 1` in `fuzz/` with dependencies available, followed by the seed test. Reverting the fuzz lock should fail the first gate.

### I18 · Important · An empty child-path argument returns the parent as a successful derivation

**Entry point** — `mk derive --path` at `crates/mk-cli/src/cmd/derive.rs:57,73–76,93,118`. The parser accepts zero relative components, and the identity derivation produces the original xpub.

```bash
"$MK" derive --in acct.mk1 --path '' --json
"$MK" derive --in acct.mk1 --path 'm/0/0' --json
```

The first exited 0, reported `relative_path: "m/"` and returned the parent unchanged at depth 3. This also happened with `m` and `m/`. The second returned a different xpub at depth 5. An empty shell variable can therefore supply a parent to a downstream consumer expecting a child.

**Fix and regression** — reject an empty path in this child-producing command before the derivation loop. Decide explicitly whether to retain an intentionally written identity spelling such as `m`, document its result if retained, and test it separately. Pin the empty-string refusal with no child output, and test `--index 0` and `--path m/0/0` as matching nonidentity controls.


## Minor findings

The first four are public low-level API cases. They were listed as untested suspicions in the October hunt and were executed directly against the freshly compiled Rust library in this audit.

### M1 · Minor · The standalone path serializer wraps the component count

`mk_codec::bytecode::encode_path`, `crates/mk-codec/src/bytecode/path.rs:85–98`. Pass `vec![ChildNumber::Normal { index: 0 }; 256].into()` as a `DerivationPath`. It emitted 258 bytes beginning `fe 00`. `decode_path` returned the empty path and left 256 unread bytes. A consumer serializing fields separately can desynchronize everything after the path. The high-level encoder enforces the ten-component limit.

**Fix and regression** — expose a checked path encoder that reports excessive depth before writing a prefix, route supported public callers through it, and address compatibility for the infallible helper. Test depths 10, 11, 255 and 256. Accepted paths must consume the whole buffer and round-trip.

### M2 · Minor · The public fragment reassembler accepts a mixed-version set

`mk_codec::string_layer::chunk::reassemble_from_chunks`, `crates/mk-codec/src/string_layer/chunk.rs:198,231–237`. Call `split_into_chunks(&[9; 70], 1)`, then set `version = 1` in the second fragment's public `StringLayerHeader::Chunked`. Reassembly returned the original 70 bytes successfully. The string-level decoder rejects the unsupported wire version. A caller working with pre-parsed fragments can silently accept a version it does not implement.

**Fix and regression** — validate the supported version on every fragment before accepting the set. Exercise a mixed set, a uniformly unsupported set and an unchanged set in reverse order. Assert an explicit version error for the first two.

### M3 · Minor · The public five-bit encoder panics on an out-of-range symbol

`mk_codec::string_layer::encode_5bit_to_string`, `crates/mk-codec/src/string_layer/bch.rs:555–564`. `encode_5bit_to_string(&[32])` indexed past the alphabet and panicked in a debug build, while `&[31]` returned `Ok`. A library caller supplying a bad symbol can lose its whole process despite the fallible API.

**Fix and regression** — validate every symbol before checksumming or indexing. Require a typed error for 32 and 255 and a successful encode for 31. Test the public function directly so a panic fails the test. Callers using the byte-to-five-bit conversion already supply bounded values.

### M4 · Minor · A public chunk header with zero total chunks panics while serializing

`mk_codec::string_layer::StringLayerHeader::to_5bit_symbols`, `crates/mk-codec/src/string_layer/header.rs:89`. Serialize `Chunked { version: 0, chunk_set_id: 0, total_chunks: 0, chunk_index: 0 }`. Checked arithmetic panicked subtracting one. A one-chunk control encodes zero in wire field six, as specified. Public callers can construct the bad enum directly. The normal splitter supplies a valid count. Also filed in `design/FOLLOWUPS.md:17` as `total-chunks-underflow-internal`.

**Fix and regression** — provide checked header construction/serialization for public consumers and validate count/index before subtraction or masking. Exercise total zero, 1 and 32, plus index equal to total. Require a typed failure for the invalid inputs and exact valid wire fields.

### M5 · Minor · The upper stub-count error reports a lower-bound violation

`mk encode --policy-id-stub`, `crates/mk-codec/src/bytecode/encode.rs:25–29` and `crates/mk-codec/src/error.rs:116`. Append 256 copies of `--policy-id-stub deadbeef` to the common `base` arguments. Exit 1, stderr `policy_id_stub_count must be >= 1`, no card. The same invocation with 255 copies succeeded with 21 chunks. The operator gets no indication that they must remove a stub. Previously filed at `design/FOLLOWUPS.md:751`.

**Fix and regression** — distinguish overflow after combining the requested and derived stubs (`crates/mk-cli/src/cmd/encode.rs:201–211`). Retain the existing zero-count vector/error and print the maximum and actual count for overflow. Test exactly 255 and 256, as well as zero.

### M6 · Minor · Decode reports a different BCH code variant when the same chunks are reordered

`mk decode --json`, `crates/mk-cli/src/cmd/decode.rs:50–56,88`. Compare `"$MK" decode --in acct.mk1 --json` with `tac acct.mk1 | "$MK" decode - --json`. The same key's two chunks measured 111 and 80 characters. The scalar `code_variant` changed from `long` to `regular`. Both calls succeeded with the same xpub. Encode's analogous field also describes just its first chunk (`crates/mk-cli/src/cmd/encode.rs:567–576`). A program selecting a layout from this field can misclassify part of the set.

**Fix and regression** — expose code variant per wire chunk index, and define or clearly label the existing scalar for compatibility. `mk inspect` already classifies each chunk. Test both input orders for the same indexed variants and decoded card.

### M7 · Minor · The text emitted by a successful correction cannot be fed back to the card reader

`mk repair` and `mk decode -`, `crates/mk-cli/src/cmd/repair.rs:541–562` and `crates/mk-cli/src/cmd/mod.rs:408–412`. Damage the final symbol of chunk two of `acct.mk1` by replacing it with `q` (`p` if already `q`). Supply both chunks to repair. Exit 5 is its documented corrected-success status. Redirect stdout to `repaired`, then run `"$MK" decode - < repaired`. It refused the generated `# Repair report` preamble with exit 1, `mixed case in input string`. The two corrected mk1 lines alone decode successfully, as does the clean repair output. This interrupts a plausible recovery pipeline exactly when correction was necessary.

**Fix and regression** — preserve the human report and JSON contract. Either teach file/stdin readers to recognize the exact generated report comments or document a copyable corrected-output pipeline using `repair --json` and `jq -r '.corrected_chunks[]'`, handling exit 5 explicitly. Test a real correction end-to-end against the original xpub. Confirm unrelated malformed lines are still diagnosed.

### M8 · Minor · The mint warning promises a permanent decoder warning that the same CLI suppresses

`mk encode --chunk-set-id`, `crates/mk-cli/src/cmd/encode.rs:394,528–536`. Append `--policy-id-stub deadbeef --chunk-set-id deadb` to `base`. Minting warned that every conforming decoder would report the mismatch forever. `mk verify --json` returned 0, no stderr, and `bundle_stamped: true`, `matches: false`. Its content-derived ID was `52bf1`. A different pin, `12345`, did produce a read warning. A holder following the mint text would misinterpret the quiet verification.

**Fix and regression** — keep the explicit-pin warning and align its text with the first-stub bundle exception at `crates/mk-cli/src/cmd/mod.rs:145–174`. Test a derived match, an ordinary mismatch and the first-stub-prefix pin, asserting mint advice and read-side behavior together.

### M9 · Minor · A correction warning can point the operator at the wrong physical plate

`mk decode`, `mk verify` and `mk repair`. `crates/mk-cli/src/cmd/mod.rs:201–229` enumerates input order. `crates/mk-cli/src/cmd/repair.rs:120,169,551` prints that ordinal as the chunk number. Reverse the two strings from M7, leaving the damage on wire chunk 1. Decode and verify warned `chunk 0: 1 correction(s)`. Repair reported `mk1 chunk 0: 1 correction at position 76`. In physical wire order chunk zero was clean. The corrected payload was intact. An operator using the diagnostic to find the degrading plate can replace the clean one.

**Fix and regression** — identify the corrected wire-header index and set ID in maintenance text. If an input ordinal is useful, label it explicitly and preserve any existing positional JSON field for compatibility. Test the same single-symbol damage in both input orders. The affected wire plate must stay constant.

### M10 · Minor · The GUI schema exposes a batch input that conflicts with its required fields

`mk gui-schema`, `crates/mk-cli/src/cmd/gui_schema.rs:110–126` and `crates/mk-cli/src/cmd/encode.rs:146`. Inspect the encode form. It lists `--in` as optional and requires both `--xpub` and `--origin-path`. It already omits `--keys`, the equivalent batch spelling. Submitting the advertised `--in keys --xpub "$X0" --origin-path m` combination exited 64. A form generated from this contract cannot use its file input.

**Fix and regression** — omit both batch spellings from this deliberately single-card form, or model the file mode separately if an actual batch GUI is added. Extract the emitted flags in the schema test and assert that neither batch spelling appears while the two single-card inputs are required. Check the GUI mirror in the same change.

### M11 · Minor · The public Rust decode example labels the master fingerprint as the xpub fingerprint

`docs/MK_CODEC_RUST_API.md:77`, the `mk_codec::decode` example prints `card.origin_fingerprint` as “xpub fingerprint”. Decode the example's two literal strings and run `mk inspect --json` on them. The origin fingerprint is `73c5da0a` and the xpub's own fingerprint is `fd13aac9`. They identify different keys. For a privacy-preserving card only the origin field is omitted. A caller checking the displayed value against the account xpub can reject the right key.

**Fix and regression** — label the field “origin fingerprint”, or print `card.xpub.fingerprint()` under the existing label. Run the sample with the two printed strings and assert the exact labeled fingerprint. Include an origin-omitted control.
